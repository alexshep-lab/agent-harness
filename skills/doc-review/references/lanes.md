# Review lanes

Each lane is one fresh reviewer with `reviewer.md` plus the lane text below. Lanes run in parallel
on the same revision. Overlap is fine; independent agreement between lanes is a signal.

## numbers — numbers and facts

Extract every numeric and factual claim about data, scope and results: counts of objects and
periods, years, shares, thresholds, probabilities, figure captions. Priority: abstract / summary,
results, conclusion, captions.

- Check each against the report it came from; for key aggregates **recompute from the data**
  when the data are available — a report can be wrong too, and a report/data mismatch is itself a
  finding.
- Check that a number's denominator matches its wording ("within the range" computed over all
  periods is a finding).
- Check internal consistency: the same number in abstract, results, discussion, conclusion and
  figures.

## frame — conclusions, framing, reliability constraints

Do not recompute numbers. Check:

1. The project's reliability constraints and reserved terms are respected.
2. Conclusions are not stronger than the data and than the limitations the project's own reports
   admit: causal wording on correlational data, generalisation beyond the covered scope,
   "proven" where the report is cautious, silence about limitations the report calls material.
3. Claims about the outside world (rules, practice, how decisions are made) have support in the
   sources or a citation — a finding only if a conclusion depends on the claim.
4. Caveats that exist somewhere in the document but do not reach the sentence they qualify.

## purpose — task, contribution, position of the authors

For papers, proposals, reports to a client, cover letters. Do not duplicate the other lanes.

1. Task and audience: can a reader state from the abstract and introduction alone what problem is
   solved, for whom, and how the result is used? If the answer appears only in the discussion, a
   reader who stops halfway never sees it.
2. Position: is the work presented as a tool/procedure for those who make and execute decisions,
   or does it read as judging other people's decisions without a basis for doing so? Quote the
   wording that does the judging.
3. Novelty: what is claimed as new; is it distinguished from existing work (including work the
   project itself says is *not* novel); is it backed by the results section?
4. Promise vs delivery: title, abstract and introduction against what is actually obtained.
5. Fit: does the document solve the task it is needed for (the chapter of a thesis, the client's
   requirement, the vacancy)?

End with an explicit answer: can the question "why does this document exist" be answered in one
paragraph quoted from the text — and quote the best candidate.

## logic (optional)

Form of reasoning only — whether conclusions follow from premises, named fallacies. Use an
existing logic skill if the project has one; it does not check facts against sources.
